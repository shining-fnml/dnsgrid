DSM DHCP reservations (API)

Configure each site's DSM DHCP interface in Settings to generate dsm-reservations-site-ID.json and dsm-request-site-ID.form. The JSON contains only ifname and the complete reservationData list for that site. The form body targets SYNO.Network.DHCPServer.Reservation.set (version 2), wrapped in SYNO.Entry.Request.

Review and back up the destination interface's existing reservations before an authenticated POST to that site's DSM server at /webapi/entry.cgi. Treat this as replacement of the entire reservation list, even when empty. Use the correct server/interface; unmanaged reservations must be merged before applying. Downloads do not authenticate or apply changes, and contain no credentials.

DSM's UI/API updates both the static reservation fragment and dhcpd.conf. Do not edit DSM system files or package services. This is reservation-only, not DHCP pools, gateway, DNS, or lease configuration. dhcpd.conf targets ISC DHCP; dhcpd-dsm.conf is retained only as a legacy audit listing, not a DSM deployment artifact.
