Only explicit publication actions write zones. Previews and downloads never validate, install, or reload. The publisher generates the configured LAN primary zone, vpn. for VPN members, and the corresponding LAN and VPN reverse zones. The temporary files are validated using named-checkzone before installation. Files are atomically replaced; the complete set must install and the immutable generation manifest must commit before one general RNDC reload is issued.

Existing regular zone files retain read/write permission bits and group ownership; new zones use mode 0644. The application owns the newly replaced inode. Symlink destinations are replaced, not followed. If preserving an existing group is unauthorized, publication fails and RNDC is not invoked. A failure during a multi-file install may leave some new files on disk, but no reload is issued; review and repair before retrying.

Successful RNDC exit confirms only that the local general reload command returned success. It does not confirm that the server loaded every intended record or that any external client can resolve it. No SFTP delivery or NAS receipt is part of DNS publication.

After all zone writes succeed, an immutable generations/dnsgrid-SERIAL/manifest.json commits checksummed generation copies. Ten committed generations are retained. Partial publication does not commit a new manifest or reload.

Legacy migration and archive compatibility retain old SOA timing values and the existing nameserver rather than changing them to new DSM defaults.

Zones start with explicit origin and TTL directives and a multiline SOA. A/PTR records have explicit FQDN owners and TTLs, are ordered alphabetically by hostname, and PTR targets are full LAN names. The final record is the zone-apex NS. Settings configures ttl, soa_ns, soa_mailbox, soa_refresh, soa_retry, soa_expire, soa_minimum, and the separate zone_ns. Persisted UTC YYYYMMDDnn serials advance only for DNS content changes or upward manual seeding; counter 99 exhaustion is rejected. Future seeds and clock rollback never lower the serial. Downloads, previews, and unchanged republication do not advance it.

DSM DHCP reservations (API)

DHCP delivery status and published artifact history

{% csrf_token %}

Publish DHCP explicitly snapshots every configured DHCP site after confirmation. NAS appliances pull only published snapshots, never these mutable previews. Inventory saves and manual downloads do not deploy reservations.

Configure each site's DSM DHCP interface in Settings to generate dsm-reservations-site-ID.json. The JSON contains only ifname and the complete reservationData list for that site.

Static hosts remain in DNS exports but are omitted from DSM DHCP reservations, even when they have a MAC address.

For local NAS-side application, manually copy only the JSON export and the repository's synology/dsm_apply.py utility onto the target NAS. Run with sudo python3 /path/to/dsm_apply.py /path/to/dsm-reservations-site-ID.json --backup-dir /path/to/backups. By default it only reads, creates private raw/restorable backups, and shows a diff. Add --apply to confirm interactively or --yes to explicitly authorize writing.

The utility uses local synowebapi --exec: SYNO.Network.DHCPServer.Reservation.get version 3 to read, then SYNO.Network.DHCPServer.Reservation.set version 2 to write, followed by a verification read. The reservationData argument is the raw JSON array, not the export's wrapper object. It requires Python 3, not Django, a web login, or root access for the web app.

Applying replaces the full reservation list for the configured interface, even when empty. Review the diff, target server/interface, and backups; merge unmanaged reservations explicitly before applying. This feature supports IPv4 only and refuses to write if current IPv6 reservations or malformed entries are present. The JSON export alone never applies changes.

User testing observed DSM updating /etc/dhcpd/dhcpd-<ifname>-static.conf, the main configuration under /etc/dhcpd/, and /etc/dhcpd/dhcpd.info during a write. Do not edit DSM system files or package services. This is reservation-only, not DHCP pools, gateway, DNS, or lease configuration.
