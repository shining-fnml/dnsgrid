DSM DHCP reservations (API)

Configure each site's DSM DHCP interface in Settings to generate dsm-reservations-site-ID.json and dsm-request-site-ID.form. The JSON contains only ifname and the complete reservationData list for that site. The form body targets SYNO.Network.DHCPServer.Reservation.set (version 2), wrapped in SYNO.Entry.Request.

For local NAS-side application, manually copy only the JSON export and the repository's synology/dsm_apply.py utility onto the target NAS. Run with sudo python3 /path/to/dsm_apply.py /path/to/dsm-reservations-site-ID.json --backup-dir /path/to/backups. By default it only reads, creates private raw/restorable backups, and shows a diff. Add --apply to confirm interactively or --yes to explicitly authorize writing.

The utility uses local synowebapi --exec: SYNO.Network.DHCPServer.Reservation.get version 3 to read, then SYNO.Network.DHCPServer.Reservation.set version 2 to write, followed by a verification read. The reservationData argument is the raw JSON array, not the export's wrapper object. It requires Python 3, not Django, a web login, or root access for the web app.

Applying replaces the full reservation list for the configured interface, even when empty. Review the diff, target server/interface, and backups; merge unmanaged reservations explicitly before applying. This feature supports IPv4 only and refuses to write if current IPv6 reservations or malformed entries are present. The JSON export alone never applies changes. The authenticated HTTP form is a separate alternative; it does not provide the local utility's safety checks.

User testing observed DSM updating /etc/dhcpd/dhcpd-<ifname>-static.conf, /etc/dhcpd/dhcpd.conf, and /etc/dhcpd/dhcpd.info during a write. Do not edit DSM system files or package services. This is reservation-only, not DHCP pools, gateway, DNS, or lease configuration. dhcpd.conf targets ISC DHCP; dhcpd-dsm.conf is retained only as a legacy audit listing, not a DSM deployment artifact.
